# CSS output

Generated by `npm run generate:css` into `dist/css/`:

- `dist/css/<id>.css`: one file per scheme (22 schemes).
- `dist/css/tol.css`: bundle of all schemes.

All properties are declared on `:root`.

| Property | Meaning |
|---|---|
| `--tol-<id>-<index>` | Colour at the data index (0-based; the same indexes used by `lut`, `discreteIndexes` and `subranges` in the JSON). |
| `--tol-<id>-<name>` | Only when the official module provides a name (qualitative sets). No names are invented. |
| `--tol-<id>-bad` | The scheme's bad-data colour, when the source gives one. |
| `--tol-<id>-gradient` | `linear-gradient(in srgb to right, ...)` for schemes meant to be interpolated (`interpolation` is `linear` or `either`). |
| `--tol-<id>-discrete-<k>` | The discrete variant when it differs from using every colour (for example nightfall uses every second colour). |
| `--tol-<id>-n<N>-<k>` | Discrete rainbow only: the k-th colour when N colours are requested (N = 1 to 23). |

Example:

```css
@import "tol.css";
.line-a { stroke: var(--tol-bright-blue); }
.line-b { stroke: var(--tol-bright-red); }
.heat   { background: var(--tol-iridescent-gradient); }
```

Semantic tokens such as `--color-primary` are deliberately not defined here; they belong to the consuming site.

Every file starts with an attribution header; see `NOTICE`.
